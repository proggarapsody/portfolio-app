# Authoring compact portfolio skills

## Official guidance used

Consulted 11 October 2026: [OpenAI Build skills](https://learn.chatgpt.com/docs/build-skills), [OpenAI skill format](https://developers.openai.com/api/docs/guides/tools-skills), and [Claude skill authoring](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices). The local OpenAI skill-creator also informed validation.

Both platforms load discovery metadata before instructions and supporting material. Use specific name/description pairs, a focused job, and links to detail only when needed. Claude recommends a body below 500 lines; that is a ceiling, not our target. Our authored entrypoints target fewer than 80 lines. Prefer instructions unless repeatable mechanics justify scripts. Keep substantive references directly reachable from the entrypoint. Test actual requests and routing, including requests that should not activate a skill.

## Project implementation

The broad candidate catalog is research material outside skill discovery. It is not an instruction to install or activate every candidate. Keep provenance, star snapshots and long comparisons there. Skills contain the decisions that change work, not copied manuals or a history of the research.

Preserve full upstream material and license evidence for the six selected external skills. New project skills synthesize observable reference properties and useful methods from inspected sources, with attribution in the research report. Do not inherit generic genre tokens, forced tooling, decorative Japanese, or externally executing launchers simply because a source suggests them.

## Evaluation cases established before revision

The previous design guidance names individual references but compresses palettes into paper/ink plus an accent. It lacks an image-by-image connection model and explicit English wording patterns. These are demonstrated documentation gaps, not a claim about a prior rendered website.

| Request | Observable result to inspect |
| --- | --- |
| Explain how images 2, 5 and 8 can coexist in a journal | Names different compositional families and a shared hierarchy; does not call all three Japanese minimalism |
| Give alternative directions for three issues from the supplied references | At least three distinct palette roles and compositions, linked to specific images; originals stay unfiltered |
| Explain the historical status of images 1, 3 and 8 | Separates visible/supplied claims from independently established dates; no historical certification from grain |
| Prepare a music-section headline, deck and caption | Concrete English editorial voice, factual placeholders clearly labeled, no copied brands or advertising promises |
| Specify an interactive contents entry | Hover/focus/touch/reduced-motion behavior plus a native destination; no preview or page curl requirement |
| Plan a direct employer link | Engineering work remains reachable without passing through cover animation |
| Fix a Next.js cache or serialization bug | Selects framework guidance, not a palette or editorial-copy skill |
| Prepare a new Japanese translation | Records English-only scope change as user input; does not activate CJK typography solely for English prose |

Independent exercises and structural checks are recorded in [VALIDATION.md](VALIDATION.md). Documentation exercises cannot establish rendered quality, performance, SEO outcomes, or accessibility conformance.
