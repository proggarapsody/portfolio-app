# Portfolio skill research and selection

Researched on 11 October 2026 in three parallel tracks: editorial design and motion; Next.js implementation; and performance, accessibility, and SEO. The selected set is the best fit among the primary-source candidates inspected for this brief, not a universal ranking of every available skill.

## Expanded research

The subsequent deeper parallel research inspected 124 records, deduplicated to 120 source entrypoints across 43 repositories. Independent pinned-source re-fetch and YAML checks confirmed **97 distinct licensed skills** under the conservative count. See [the full catalog](research/CATALOG.md), [source-specific synthesis](research/SYNTHESIS.md), [eight image analyses](research/image-evidence.md), [visual connections and wording](research/VISUAL-CONNECTIONS.md), [seven palettes](research/PALETTES.md), [existing hooks](research/HOOKS.md), and [official authoring guidance](research/AUTHORING.md). This supersedes the initial narrow discovery coverage below.

## Selection criteria

Prefer an identifiable upstream source, useful instructions and references, compatibility with Next.js/Vercel, clear separation of responsibilities, modest tool requirements, and minimal conflict with the confirmed art direction. Popularity alone is not a selection criterion. Install whole selected skill folders at pinned revisions, preserve license evidence, and load references only when needed.

## Reproducibility and local adaptations

The exact repositories, source paths, revisions, license declarations, file counts, and local tree hashes are recorded in [skills.lock.json](../.agents/skills.lock.json). This is a provenance manifest, not a package-manager lockfile or an auto-updater.

- Preserved the full upstream MIT licenses alongside the Addy and Jakub skill copies.
- Vercel's skill frontmatter and repository README declare MIT. No complete LICENSE/COPYING/NOTICE file was present in the inspected pinned repository; preserve its declarations and author metadata without inventing a copyright notice. See [third-party notices](../THIRD_PARTY_NOTICES.md).
- Replaced five links to omitted Addy sibling skills with pinned upstream URLs. They are optional further references, not installed local workflows.
- Fixed three compiled React guide links by pointing them to the existing `rules/` files. The normal entrypoint and individual rules remain the preferred reading path.
- Kept visual overrides in project AGENTS.md and the custom design skill rather than rewriting upstream aesthetic advice.

To update, compare the candidate revision's instructions, dependencies, references, and license evidence first. Install into a temporary directory with the skill installer at an explicit revision, compare with the local copy, reapply the recorded link adaptations, validate references/frontmatter, then update the manifest and research date. Do not blindly replace the whole directory or pull floating main during ordinary development.

## Primary implementation sources

- [Next.js agent documentation](https://nextjs.org/docs/app/guides/ai-agents): version-matched bundled documentation and managed agent instructions. Preserve project instructions when a framework-managed block is added.
- [Server and Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components), [static route parameters](https://nextjs.org/docs/app/api-reference/functions/generate-static-params), [images](https://nextjs.org/docs/app/getting-started/images), and [metadata](https://nextjs.org/docs/app/getting-started/metadata-and-og-images): consult the installed version before implementation. Server Components alone do not guarantee build-time prerendering.
- [Google Web Vitals](https://web.dev/articles/vitals): field thresholds and percentile interpretation; laboratory results do not establish field INP.
- [Google JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics) and [lazy-loading guidance](https://developers.google.com/search/docs/crawling-indexing/javascript/lazy-loading): crawlable destinations and content that does not require interaction. The portfolio's permanent routes plus optional page transitions apply these principles.
- [W3C dragging movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) and [animation from interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html): provide click/tap alternatives to dragging. Reduced-motion behavior is a confirmed product requirement; interaction-animation suppression is not itself an AA criterion.

## Validation boundary

Preparation validation checks skill metadata, file/reference integrity, preserved reference assets, and the consistency of the written deliverables. It does not prove agent adherence, visual quality, accessibility conformance, SEO outcomes, or runtime performance. Those require a future implementation and the checks in the development plan.

Checks completed on 11 October 2026: the initial six skill entrypoints passed the skill-creator validator; all local Markdown file targets resolved; all eight copied reference images matched their sources byte for byte; no symlinks were introduced. Upstream skill trees and reference images have recorded SHA-256 digests. External URL availability and every upstream heading anchor were not part of the local-link check. The YAML validator ran in a temporary environment without adding dependencies to this project.

Expanded verification and the two independent documentation exercises are recorded in [VALIDATION.md](research/VALIDATION.md). Ten skill folders now have current hashes in the lock; no hook configuration or application was added.
